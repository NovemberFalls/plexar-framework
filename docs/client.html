How it works

  1. Generate. Describe what you want. A planner splits it into small tasks, each with a check.
  2. Approve. A named person approves the plan (or a batch of tasks) once. Nothing runs before that.
  3. Run. An agent does each task on its own branch, in order: a task starts only when the ones it waits for are done.
  4. Check. The gate (your tests) and the task's own check decide pass or fail, not the agent's opinion.
  5. Review. A verifier runs the work and takes screenshots; an approver reads everything and approves or sends it back.
  6. Evaluate. You look at the evidence and keep it, send it back with a note, or reject it.

Words on this board

Bucket
One repository the framework works in, with its runner, gate and reviewers.
Plan
A goal split into tasks, approved once, run in order on its own branch.
Task
One prompt for an agent, small enough to check.
Lane
How hard or risky a task is, which picks the model: critical, workhorse or mundane.
Waits for
Tasks that must finish first, because this one builds on their work.
Check
A command that must fail before the task and pass after it, so it proves the task was done.
Gate
The repository's own tests, run after every task. Exit code 0 is a pass.
Verifier
A model one tier up that runs the work, takes screenshots and passes or fails it.
Approver
The top model tier: reads the verifier's evidence and approves or sends it back.
Question
An agent that is unsure asks instead of guessing; reviewers answer if they can, otherwise you do.

Task states

Held
Written, not yet approved to run.
Queued
Approved, waiting for its turn (one task runs at a time per repository).
Running
An agent is working on it; the live bar shows which step.
Done
The gate and its check passed; waiting for your verdict in Evaluate.
Failed
The gate or check failed after the retries; the evidence says why.
